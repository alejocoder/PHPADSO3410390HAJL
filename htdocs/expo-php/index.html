in_array()

Verificación de pertenencia dentro de un arreglo

1. ¿Para qué sirve?

Busca un valor determinado dentro de un array. Devuelve true si el elemento se encuentra en el arreglo y false en caso contrario. Es ideal para validar permisos, roles, extensiones de archivo permitidas o selecciones de usuario.

2. Sintaxis y Parámetros 

in_array(mixed $needle, array $haystack, bool $strict = false): bool
  • $needle: El valor buscado (aguja).
  • $haystack: El arreglo en el que se realiza la búsqueda (pajar).
  • $strict: (Opcional) Si se define como true, evalúa también el tipo de dato (coincidencia estricta).

3. Ejemplos Prácticos & Simulación

Nivel Básico: Verificación Simple 
<?php
$frutas = ["manzana", "banana", "naranja"];
$busqueda = "$VALOR_BUSQUEDA";

if (in_array($busqueda, $frutas)) {
    echo "¡'$busqueda' encontrada!";
} else {
    echo "'$busqueda' NO está en la lista.";
}
?>
Nivel Intermedio: Control de Permisos 
<?php
$rolesPermitidos = ['admin', 'editor', 'superadmin'];
$usuarioRol = "$ROL_SELECCIONADO";

if (!in_array($usuarioRol, $rolesPermitidos)) {
    echo "HTTP 403: Acceso Denegado para rol '$usuarioRol'.";
} else {
    echo "HTTP 200: Bienvenido al panel con rol '$usuarioRol'.";
}
?>
Nivel Avanzado: Comparación Estricta vs No Estricta 
<?php
$codigosValidos = [100, 200, 300]; // Arreglo de Integers
$entrada = "$VALOR_ENTRADA";       // String

$noEstricto = in_array($entrada, $codigosValidos, false);
$estricto   = in_array($entrada, $codigosValidos, true);
?>

4. Errores Comunes y Buenas Prácticas

  • Error: Olvidar el parámetro estricto $strict = true. Sin esto, cadenas no numéricas pueden coincidir inesperadamente con 0 en comparaciones débiles.
  • Buena Práctica: Pasa siempre true como tercer parámetro a menos que explícitamente requieras coerción de tipos.

mysql vs mysqli vs PDO

Qué usar hoy, qué quedó obsoleto y cómo migrar sin romper la aplicación

1. Contexto: la extensión mysql_* ya no existe

La extensión original mysql_* fue deprecada en PHP 5.5 y eliminada en PHP 7.0. Sus funciones (mysql_connect(), mysql_query(), mysql_fetch_assoc()) provocan un Fatal error en cualquier versión moderna. mysqli significa MySQL Improved y es la evolución oficial para MySQL/MariaDB; PDO es una capa de abstracción que permite trabajar con más de una docena de motores.

2. Comparativa rápida

Característica mysql_* mysqli PDO
Estado Eliminada (PHP 7.0) Activa Activa
Motores Solo MySQL MySQL / MariaDB MySQL, PostgreSQL, SQLite, SQL Server…
Estilo Solo procedural POO y procedural Solo POO
Prepared statements No Sí (?) Sí (? y :nombre)
Transacciones Muy limitadas Sí Sí
Errores Warnings silenciosos Excepciones opcionales Excepciones configurables
Recomendación Nunca Proyectos solo MySQL Proyectos multi-motor

3. El mismo SELECT en las tres APIs

API antigua: mysql_* (no ejecutable en PHP 7+) 
<?php
// ❌ Fatal error en PHP 7+: Call to undefined function mysql_connect()
$link = mysql_connect('localhost', 'root', 'secret');
mysql_select_db('tienda', $link);

$result = mysql_query("SELECT * FROM users WHERE id = $id");
while ($row = mysql_fetch_assoc($result)) {
    echo $row['email'];
}
?>

Sin prepared statements, sin POO y sin transacciones fiables: código inseguro e imposible de mantener.

Migración a mysqli (POO + prepared statement) 
<?php
$db = new mysqli('localhost', 'root', 'secret', 'tienda');
$db->set_charset('utf8mb4');

$stmt = $db->prepare('SELECT email FROM users WHERE id = ?');
$stmt->bind_param('i', $id);
$stmt->execute();

$result = $stmt->get_result();
while ($row = $result->fetch_assoc()) {
    echo htmlspecialchars($row['email']);
}
$stmt->close();
$db->close();
?>
Alternativa moderna: PDO (parámetros con nombre) 
<?php
$pdo = new PDO(
    'mysql:host=localhost;dbname=tienda;charset=utf8mb4',
    'root',
    'secret',
    [
        PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    ]
);

$stmt = $pdo->prepare('SELECT email FROM users WHERE id = :id');
$stmt->execute([':id' => $id]);

foreach ($stmt as $row) {
    echo htmlspecialchars($row['email']);
}
?>

PDO permite cambiar de motor de base de datos sin reescribir toda la capa de acceso a datos.

4. Inyección SQL: código vulnerable vs código seguro

❌ Concatenación directa

$id  = $_GET['id']; // "1 OR 1=1"
$sql = "SELECT * FROM users
        WHERE id = $id";
$result = $db->query($sql);
// Devuelve TODOS los usuarios

✅ Parámetro preparado

$stmt = $db->prepare(
    'SELECT * FROM users WHERE id = ?'
);
$stmt->bind_param('i', $_GET['id']);
$stmt->execute();
// Solo devuelve 0 o 1 fila
Simulador: elige la API y prueba una entrada maliciosa

5. Chuleta de migración de mysql_* a mysqli

Antes (mysql_*) Ahora (mysqli)
mysql_connect()new mysqli() / mysqli_connect()
mysql_select_db()$db->select_db() / 4.º argumento
mysql_query()$db->query() / $db->prepare()
mysql_fetch_assoc()$result->fetch_assoc()
mysql_real_escape_string()Prepared statements
mysql_error()$db->error / mysqli_sql_exception
mysql_close()$db->close()

mysql_*

Solo valor histórico. No lo uses en código nuevo ni en migraciones parciales.

mysqli

Ideal si tu proyecto depende exclusivamente de MySQL/MariaDB y quieres POO o estilo procedural.

PDO

Mejor opción si prevés cambiar de motor o necesitas parámetros con nombre y una API uniforme.

6. Errores comunes y buenas prácticas

  • Error: copiar tutoriales antiguos con mysql_query(). Ese código ya no se ejecuta en PHP 7+.
  • Error: creer que cambiar mysql_ por mysqli_ hace el código seguro. Si sigues concatenando variables, la inyección SQL continúa.
  • Buena Práctica: migra siempre a prepared statements, define utf8mb4 y maneja los errores con excepciones, no con or die().

mysqli: conexión, consultas y transacciones

API oficial para MySQL/MariaDB con POO, prepared statements y transacciones

1. ¿Para qué sirve?

Extensión para conectar y consultar bases de datos MySQL/MariaDB con soporte de sentencias preparadas y transacciones. Es la evolución directa de la antigua mysql_* (eliminada en PHP 7.0). Puedes usarla con estilo POO (recomendado) o procedural.

2. Sintaxis

Estilo POO (recomendado)

$db = new mysqli($host, $user, $pass, $dbname);
$db->set_charset('utf8mb4');

Estilo procedural (heredado)

$db = mysqli_connect($host, $user, $pass, $dbname);
mysqli_set_charset($db, 'utf8mb4');

Ambos estilos usan el mismo motor, pero no conviene mezclarlos en un mismo proyecto. El estilo POO facilita el tipado, las excepciones y las pruebas.

2.1 Manejo moderno de errores

Por defecto, mysqli puede fallar de forma silenciosa. Activa excepciones para detectar errores de conexión, SQL o transacción:

<?php
mysqli_report(MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT);

try {
    $db = new mysqli($host, $user, $pass, $dbname);
    $db->set_charset('utf8mb4');
} catch (mysqli_sql_exception $e) {
    error_log($e->getMessage());
    exit('No se pudo conectar a la base de datos.');
}
?>

3. Ejemplos Prácticos & Simulación

Nivel Básico: Conexión Inicial 
<?php
mysqli_report(MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT);

try {
    $db = new mysqli('localhost', 'root', 'secret', 'demo');
    $db->set_charset('utf8mb4');
    echo "Conexión exitosa a MySQL 8.0";
} catch (mysqli_sql_exception $e) {
    error_log($e->getMessage());
    echo "Error de conexión. Revisa el log.";
}
?>
Nivel Intermedio: Prepared Statements 
<?php
$stmt = $db->prepare('SELECT id, email FROM users WHERE email = ?');
$stmt->bind_param('s', $email); // 's' = string
$stmt->execute();

$result = $stmt->get_result();
while ($row = $result->fetch_assoc()) {
    echo htmlspecialchars($row['email']);
}

$stmt->close();
?>
i = integer
d = double
s = string
b = blob
Nivel Avanzado: Transacción Bancaria ACID 
<?php
$db->begin_transaction();

try {
    $db->query("UPDATE cuentas SET saldo = saldo - 500 WHERE id = 1");

    $saldo = $db->query("SELECT saldo FROM cuentas WHERE id = 1")
                ->fetch_column();

    if ($saldo < 0) {
        throw new RuntimeException('Fondos insuficientes');
    }

    $db->query("UPDATE cuentas SET saldo = saldo + 500 WHERE id = 2");
    $db->commit();
} catch (Throwable $e) {
    $db->rollback();
    error_log($e->getMessage());
}
?>
Nivel Experto: CRUD con prepared statements 
<?php
// INSERT seguro: los tipos 'ss' indican dos strings
$stmt = $db->prepare(
    'INSERT INTO users (email, nombre) VALUES (?, ?)'
);
$stmt->bind_param('ss', $email, $nombre);
$stmt->execute();

echo 'ID insertado: ' . $db->insert_id;
$stmt->close();
?>

4. Errores comunes y buenas prácticas

  • Error: concatenar variables en la consulta. Los prepared statements no son opcionales: son la defensa principal contra inyección SQL.
  • Error: usar or die() o mostrar $db->error al usuario. Filtra información sensible y registra el error en el log.
  • Error: olvidar set_charset('utf8mb4'). Sin ello pueden aparecer caracteres corruptos y problemas con emojis.
  • Buena Práctica: cierra $stmt y $db al terminar, usa un usuario de BD con privilegios mínimos y envuelve las transacciones en try/catch.

require(): inclusión obligatoria

Inclusión obligatoria de archivos externos

1. ¿Para qué sirve?

Incluye y evalúa el archivo especificado. Si el archivo no existe, lanza un Fatal Error y detiene la aplicación. Es la opción correcta para dependencias críticas: configuración, conexión a base de datos, clases o funciones sin las cuales la app no puede continuar.

1.1 Las cuatro variantes de inclusión

Directiva Si el archivo falta ¿Repite la carga? Uso típico
include Warning y continúa Sí Fragmentos opcionales (banners, widgets)
include_once Warning y continúa No Helpers opcionales
require Fatal Error y detiene Sí Dependencias obligatorias y templates
require_once Fatal Error y detiene No Clases, funciones, configuración y bootstrap

Regla práctica: si el archivo define clases o funciones, usa *_once; si solo imprime HTML o devuelve datos, require o include suele ser suficiente.

2. Sintaxis 

require __DIR__ . '/header.php';

3. Ejemplos Prácticos & Simulación

4. Buenas Prácticas

  • Usa siempre __DIR__ (o dirname(__FILE__)) para construir rutas absolutas y evitar fallos según el directorio de trabajo.
  • No uses require con datos que vengan del usuario: permitirías incluir archivos arbitrarios (Local File Inclusion).
  • Recuerda que require devuelve el valor del return del archivo incluido; por eso se usa para cargar arrays de configuración.

require_once()

Inclusión única garantizada sin duplicados

1. ¿Para qué sirve?

Funciona igual a require, pero verifica si el archivo ya se cargó previamente para no incluirlo dos veces y evitar colisiones de funciones/clases. Si el archivo no existe, también lanza un Fatal Error y detiene la ejecución.

1.1 ¿Cómo sabe PHP que un archivo ya fue incluido?

PHP no compara el texto de la ruta: resuelve la ruta real del archivo (realpath) y la guarda en una lista interna de archivos incluidos. Por eso estas dos llamadas se consideran el mismo archivo y la segunda se ignora: 

<?php
require_once __DIR__ . '/../app/helpers.php';
require_once __DIR__ . '/../app/./helpers.php'; // Misma ruta real: ignorado
?>

Cuidado con mayúsculas/minúsculas en sistemas sensibles a ellas (Linux) y con enlaces simbólicos: si dos rutas resuelven al mismo archivo real, require_once lo detecta; si apuntan a copias distintas, no.

2. Sintaxis 

require_once __DIR__ . '/lib/Database.php';

3. Ejemplos Prácticos & Simulación

Inicializar App Bootstrap

4. Buenas Prácticas

  • Ideal para archivos que definen clases, funciones, constantes o configuración: evita el fatal Cannot redeclare.
  • En proyectos modernos, el autoload de Composer (vendor/autoload.php) reemplaza la mayoría de estos require_once manuales.
  • No lo uses como excusa para incluir todo desde cualquier parte: mantén una única responsabilidad y un punto de entrada claro (bootstrap).

session_start()

Gestión de persistencia de datos y sesiones de usuario

1. ¿Para qué sirve?

Inicializa una nueva sesión o reanuda la existente para persistir variables en la superglobal $_SESSION.

2. Sintaxis 

session_start(array $options = []): bool

2.1 Ciclo de vida de una sesión

1

session_start()

Crea o reanuda la sesión y envía la cookie PHPSESSID.

2

$_SESSION[...]

Lees y escribes datos en el servidor.

3

session_write_close()

Guarda y libera el bloqueo del archivo de sesión.

4

session_destroy()

Elimina la sesión del servidor (logout).

Importante: PHP bloquea el archivo de sesión mientras el script se ejecuta. En peticiones largas o AJAX concurrentes, llama a session_write_close() en cuanto termines de modificar $_SESSION para no serializar las peticiones.

2.2 Opciones recomendadas de seguridad

Opción Valor Efecto
cookie_httponlytrueLa cookie no es accesible desde JavaScript (mitiga XSS).
cookie_samesite'Lax' o 'Strict'Limita el envío de la cookie en peticiones cross-site (mitiga CSRF).
cookie_securetrueSolo se envía por HTTPS. Obligatorio en producción.
use_strict_mode1Rechaza IDs de sesión no generados por el servidor (anti-fixation).
gc_maxlifetime1800Tiempo de inactividad antes de que la sesión caduque (segundos).

?>
Nivel Intermedio: Regeneración de ID (Anti-Fixation)

?>
Regenerar Cookie de Sesión
Nivel Avanzado: Configuración de Cookies HttpOnly + SameSite 
<?php
session_start([
    'cookie_httponly' => true,
    'cookie_samesite' => 'Lax',
    'cookie_secure'   => true,
    'use_strict_mode' => true,

Testear Banderas de Seguridad
Nivel Experto: login seguro + logout completo 
<?php
session_start([
    'cookie_httponly' => true,
    'cookie_samesite' => 'Lax',
    'cookie_secure'   => true,  // Solo HTTPS
    'use_strict_mode' => true,
]);

// 1. Tras validar credenciales
$_SESSION['user_id'] = $user['id'];
$_SESSION['role']    = $user['role'];
session_regenerate_id(true); // Evita fijación de sesión

// 2. Logout
$_SESSION = [];
if (ini_get('session.use_cookies')) {
    $p = session_get_cookie_params();
    setcookie(session_name(), '', time() - 42000,
        $p['path'], $p['domain'],
        $p['secure'], $p['httponly']);
}
session_destroy();
?>
Patrón: mensajes flash de una sola lectura 
<?php
session_start();

// Petición 1: guardar el mensaje
$_SESSION['flash'] = 'Usuario actualizado correctamente';

// Petición 2 (redirección): leer y borrar
$mensaje = $_SESSION['flash'] ?? null;
unset($_SESSION['flash']);

echo htmlspecialchars($mensaje ?? '');
?>

Los mensajes flash viven un solo ciclo: se muestran una vez y se eliminan para no repetirse al recargar.

4. Errores comunes y buenas prácticas

  • Error: llamar a session_start() después de imprimir HTML. Provoca Headers already sent; debe ir al inicio absoluto del script.
  • Error: no regenerar el ID tras el login. Un atacante podría fijar la sesión de la víctima (session fixation).
  • Error: creer que session_destroy() borra la cookie. También hay que vaciar $_SESSION y caducar la cookie con setcookie().
  • Buena Práctica: usa HTTPS, cookie_httponly, cookie_samesite, cookie_secure y use_strict_mode. No guardes contraseñas ni datos sensibles en la sesión.
  • Buena Práctica: cierra la escritura con session_write_close() en procesos largos para liberar el bloqueo del archivo de sesión.
